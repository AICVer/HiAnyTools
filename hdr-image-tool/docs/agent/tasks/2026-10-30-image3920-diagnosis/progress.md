## 已确认的完整原因链

**JPEG浮点解码保留范围外重建值 → iOS默认低质量缩采样可保留这些值 → 坐标计算没有单列非物理XYZ → 二维出现不可能色度，CAM16也产生离群点。**

1. 该图的Core Image原尺寸浮点结果已经存在负值，不是所有负值都由缩采样新产生。macOS扫描2592000像素，39947个含负BT.2020 RGB、33054个含负XYZ；RGB最低约(-0.001459,-0.001795,-0.010794)，最高约(1.066943,1.010297,1.035270)。这些为Apple浮点处理结果，不是原始JPEG存有负的8位码值。
2. 独立Pillow以YCbCr解码，JFIF全范围矩阵不裁切重建时，编码RGB最小约(-0.043216,-0.034469,-0.133208)，149420像素含负分量，支持JPEG重建范围外值这一来源。JPEG为4:2:0（Pillow sampling code 2）。Pillow与Apple的解码、色度重采样精度不同，此数量不要求与Apple逐像素相同。
3. 当前`PixelDistribution.swift:124`只用`transformed(by:)`，没有显式设置`highQualityDownsample`。本机SDK `CIContext.h:124`起明确注明：macOS默认true，其他平台默认false；`CIImage.h:460`起注明显式参数会覆盖context默认。高质量为多次缩采样，低质量为单次，因而之前macOS测试采用了不同的默认行为。
4. 在macOS将同一生产渲染入口显式设为false，即复现截图的点云形状、三个异常点和xy无定义1。这是对iOS默认配置的本地复算；不是在iOS27模拟器中复现。
5. `PixelColorMath.point`只检查xy分母为正、CAM16输出有限等，没有检验XYZ是否非负。有限的负XYZ仍可产生数值坐标；分母很小的暗部会进一步放大xy偏移。当前invalidCount统计NaN/Inf，不包含这些有限但非物理的XYZ。
6. 同一组输入同时进入Lab/CAM16-UCS，所以三维暗部离群与二维异常具有共同上游来源。CAM16返回有限数值不等于输入物理有效。ICtCp会因LMS越域排除其中部分点，三模型之间的有效计数也会不同。

## 与上一轮结论的关系和修复建议

- 上轮确定的分面网格近似误差仍存在，但不能解释本截图二维图上x+y>1等明显离群；本图为sRGB SDR，也不适用P3原色真实超BT.2020的解释。10000nit默认要求仍待实施，与此问题分开。
- 最小修复方向：显式统一分析缩采样设置，消除macOS/iOS默认差异；把非物理XYZ、无定义色度、PQ/LMS越域和普通无效数值分别统计，二维与三维共用有效性判断。
- 高质量缩采样能消除本样本这批离群，但会改变采样平均结果，不能保证任意图片解码的负值均消失，不能替代输入有效性检查。
- 若需要严格的“原始SDR像素”分析，应明确SDR解码后的源RGB范围契约；本轮8位SDR光栅对照证明入口语义有影响，但未擅自选择或实施通用量化策略。
- 不可直接把所有BT.2020负RGB裁零。合法P3等原色变换本来可能产生负BT.2020分量；应区分参考原色越界与非物理XYZ，避免改变有效颜色的色度。
- 本轮不添加亮度阈值来隐藏暗部点，不修改原图，不将高质量对照称为App已修复。
